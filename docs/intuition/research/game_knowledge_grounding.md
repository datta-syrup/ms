# Game knowledge grounding for a proactive MapleStory companion (MapleSyrup)

Status: COMPLETE (2026-11-01). All cited pages were opened; facts not confirmed from an opened page are listed under Gaps. Note on scope: the user's own play is on live Heroic/Reboot MapleStory (from memory), but MapleSyrup launched around Classic World, so Classic World facts are treated as the primary target and version-scoping is a recurring theme below.

Scope: (1) structured MapleStory data sources and their terms, (2) the facts behind the founder's example (Kerning City PQ in Classic World; Henesys / Henesys Hunting Ground / Ellinia BGM), (3) remark-hook knowledge graph and novelty-based selection, (4) grounding suggestions in the player's real state.

## Key Question 1: Which structured MapleStory data sources exist, and under what terms?

### Takeaway
Machine-readable map/BGM/NPC/quest data exists only in unofficial, WZ-derived sources — chiefly maplestory.io (verified live: per-map `backgroundMusic` such as "Bgm00/FloralLife" and "Bgm02/WhenTheMorningComes", NPC IDs, portals, mobs; no license, AS-IS) — while Classic World-specific facts live in fan wikis/databases with non-commercial or permission-required terms (mapleclassic.wiki CC BY-NC-SA 4.0; maplestorywiki.net CC BY-NC-SA 3.0; NiaMeowDB: facts reusable with credit, bulk/product use needs written permission). Nexon's official Open API covers character data for KMS/TMS/MSEA only (daily refresh, ~500 req/day/key per a community client), not GMS or Classic World, and Nexon's EULA forbids reverse engineering and non-personal use of client content.

### Inferences
- For a per-map "remark hook" graph, the most machine-friendly source is maplestory.io's map endpoint (map details + `/bgm` + NPCs + portals), but it is an unofficial, AS-IS service with no stated license or SLA and, per its own disclaimer, all underlying content is Nexon's; MapleSyrup should cache locally, treat it as a build-time data source rather than a runtime dependency, and keep a provenance field per fact.
- Classic World-specific facts (level ranges, PQ tuning, drop tables) are only in fan sources (NiaMeowDB, mapleclassic.wiki) as of Nov 2026; both have licenses that forbid building a product "mostly from" their collection (meowdb) or commercial use (CC BY-NC-SA on mapleclassic.wiki) — so facts should be re-derived or licensed, and attribution-with-link offered where excerpts are used.
- The Nexon Open API is character-centric (level, job, equipment, union, guild) and region-keyed (KMS/TMS/MSEA per the SDK); it does not appear to cover GMS or Classic World, and it is not real-time, so it cannot replace syrup's live screen reading for "state at this moment"; at best it is a once-per-session enrichment source where available.

### Gaps
- Nexon Open API: the official games list, rate limits, data refresh timing (reported by community to be daily), and whether GMS/Classic World are exposed — pages are JS-rendered; not confirmed from the official site. The SDK's region list (KMS, TMS, MSEA) is the best evidence found.
- The Nexon Open API Terms and Conditions and the "AI Agent Guide" content were not retrievable.
- Hidden Street (hidden-street.net) and the Fandom MapleStory Wiki (maplestory.fandom.com) returned errors on fetch, so their current coverage and license text are unverified here (Fandom wikis are generally CC BY-SA, but this was not confirmed from the page).
- The maplestory.io repo's license could not be confirmed (no LICENSE visible in the README excerpt); treat the data service as unlicensed/AS-IS until confirmed with the operators (hello@crr.io).
- Whether maplestory.io hosts any Classic World data version (it serves GMS by version number; Classic World's client version was not identified) is unknown — a Classic World hook table would need its own data source or in-game observation.

## Key Question 2: The facts behind the example (Kerning City PQ; Henesys / Henesys Hunting Ground / Ellinia music)

### Takeaway
In MapleStory Classic World (Grand Launch 2026-10-21, 11:00 PDT, Windows/Mac via Nexon Launcher or Steam) the Kerning City Party Quest ("First Time Together") exists with Classic-specific tuning per the best fan guide (updated 2026-10-23): level 21+ with no observed cap, exactly 4 members, NPC Lakelis, 30-minute limit, King Slime boss (Lv 32, 16,820 HP, 2,400 EXP at launch), Squishy Shoes and Companion's Magic Box rewards — very different from the same-named modern GMS PQ (Lv 70+, 20 min). Official BGM titles (confirmed on Nexon's 2021 anniversary OST and the maplestory.io data): Henesys = "Floral Life", Ellinia = "When The Morning Comes" (not "Missing You"), Lith Harbor = "Above The Treetops", Kerning City = "Bad Guys", Orbis = "Shinin' Harbor"; the Classic database adds Henesys Hunting Ground I–III = "Cava Bien" and Perion = "Nightmare". Per-track composer credits could not be confirmed from any authoritative source (official albums credit CODA SOUND / Studio EIM / ASTERIA collectively; community sites say soundTeMP), so the companion should not name a composer.

### Inferences
- The founder's example ("that'll level you up two levels really fast") is plausible for a low-20s character in Classic World given 2,400 EXP from King Slime plus stage EXP, but the exact level gain depends on the player's level; the companion should compute it from an EXP table rather than assert "two levels".
- Composer attribution for the Victoria Island BGM is NOT reliably established by the sources opened so far: community aggregators (OCRemix) credit soundTeMP at the game level, but Wikipedia's SoundTeMP article omits MapleStory, the official 18th-anniversary OST lists no composers, and the Budapest album credits original scores collectively to CODA SOUND / Studio EIM / ASTERIA. A companion should therefore talk about the music by title and mood (which are confirmed) and avoid naming a composer unless a track-level credit is found.
- The founder's example line "the piano there is insane" about Ellinia is consistent with community reception (TV Tropes notes piano versions of the Ellinia theme are especially loved), so "piano" is a defensible hook for Ellinia's music — but it should be stored as a community-sentiment fact with its source, not as a composer/instrumentation fact.
- Same-named content differs by version (KPQ: Lv 21+/30 min in Classic World vs Lv 70+/20 min in modern GMS). Every fact in the knowledge graph needs a version/world scope (classic_world | gms_live | kms ...) and the companion must select by the world syrup detects (e.g. Classic World login screen or world name), otherwise it will confidently say wrong things.
- Humming: Nexon's streaming statement forbids distributing game music assets separately; a companion humming a melody (its own synthesized rendition, not the audio asset) is a different act, but music copyright in the melody itself is a separate question not answered by these sources — flag for legal review before shipping "hum the Ellinia theme".

## Key Question 3: Remark-hook knowledge graph and novelty-based selection

### Takeaway
Three proven patterns map directly onto MapleSyrup: (a) Valve's response-rules system (GDC 2012) and Hades' condition-checking system — remarks are data rows with criteria over hundreds of world facts, matched most-specific-first, weighted, with "characters that remember history"; (b) Generative Agents (2023) — candidates scored by recency (exponential decay, factor 0.995), importance (LLM-rated 1–10) and relevance (embedding cosine), min–max normalized and summed, plus periodic "reflection" that turns raw observations into higher-level insights (e.g. "this player prefers Ellinia's music"); (c) a decoupled, low-latency "when to speak" gate (DiscussLLM's silent token / classifier–generator split; ProactiveLLM's sufficiency head; Moshi-style full-duplex models at ~200 ms) separate from phrasing. Together they give a data-driven, no-magic-strings design: hooks and facts in tables, selection by scoring with cooldowns, phrasing by the realtime voice model.

### Cited Findings
- Valve's GDC 2012 session (Elan Ruskin, Programming track) describes the system behind Left 4 Dead's responsive dialog: "hundreds of facts about the game world" are fuzzy-pattern-matched against "a database of thousands of possible lines" (example: "Pills here!"); stated takeaways: "A uniform mechanism for tracking thousands of facts and possibilities", "Characters that remember history", "Matching that moves from special cases to general ones", selecting "the best dialog, script, behavior, or animation for a situation", and "A writer-friendly interface for special cases, running gags, and new tracked facts, without programmers changing thousands of lines of code" — [GDC Vault 1015317](https://gdcvault.com/play/1015317/AI-driven-Dynamic-Dialog-through)
- Emily Short's write-up of the same talk: dialogue snippets are matched to a continually changing world state; the system "prioritizes rules and applies the most specific one it can find", using less-specific rules as fallbacks; design goals were that writers can author a lot of content easily and the system responds to many situations (e.g. a special quip when attacked in a particular environment); characters exchange quips but break off when one is attacked; characters "don't use dialogue to pursue goals" but create an impression of situational awareness; the talk also covered lookup optimization and writer-comfortable tools — [Emily Short, GDC 2012 talk on dynamic dialogue](https://emshort.blog/2012/03/16/gdc-2012-talk-on-dynamic-dialogue/)
- Generative Agents (Park, O'Brien, Cai, Morris, Liang, Bernstein; arXiv 2304.03442, Apr 2023, rev. Aug 2023): memory stream = "a database that maintains a comprehensive record of an agent's experience"; each memory object has a natural-language description, creation timestamp and most-recent-access timestamp — [arXiv 2304.03442 (PDF)](https://arxiv.org/pdf/2304.03442v2); abstract — [arXiv abs](https://arxiv.org/abs/2304.03442)
- Generative Agents retrieval: recency = exponential decay over game hours since last retrieval with decay factor 0.995; importance = an LLM-rated integer "On the scale of 1 to 10" where 1 is purely mundane and 10 extremely poignant (examples: 2 for cleaning a room, 8 for asking a crush out), assigned when the memory is created; relevance = cosine similarity between the memory's embedding and the query's embedding; the three scores are min–max scaled to [0,1] and summed with weights all set to 1; top-ranked memories that fit the context window go into the prompt — [arXiv 2304.03442 (PDF)](https://arxiv.org/pdf/2304.03442v2)
- Generative Agents reflection: triggered when the sum of importance scores of recent events exceeds 150 (roughly two or three times a day); the LLM gets the 100 most recent records and is asked for the three most salient high-level questions, which become retrieval queries; retrieved memories yield insights that cite supporting record numbers ("because of 1, 5, 3"), stored as new reflections linked to sources — [arXiv 2304.03442 (PDF)](https://arxiv.org/pdf/2304.03442v2)
- Generative Agents reacting: at each step the LLM decides whether to keep the current plan or react to a new observation, given the agent summary, current status, the observation and a context summary built from two retrieval queries (the agent's relationship with the observed entity, and the entity's current action); if it reacts, the plan is regenerated from that point; example: John sees Eddy in the garden and the model suggests John ask about Eddy's music composition — [arXiv 2304.03442 (PDF)](https://arxiv.org/pdf/2304.03442v2)
- Generative Agents failure modes: retrieval failures (an agent said "I haven't been following the election too closely" despite having heard about the candidacy); embellishment/hallucination (an agent added that someone "is going to make an announcement tomorrow", never discussed; another described a neighbor as the author of Wealth of Nations from the model's world knowledge); overly formal speech attributed to instruction tuning (stiff greetings/pleasantries); agents rarely refusing suggestions and drifting toward others' interests; misreading physical norms (one-person bathroom, entering closed shops) — [arXiv 2304.03442 (PDF)](https://arxiv.org/pdf/2304.03442v2)
- DiscussLLM (Patel, Melvin, Malon, Min; arXiv 2508.18167, Aug 2025, v2 May 2026) frames LLMs' reactive-only behavior as an "awareness gap"; builds a two-stage pipeline generating multi-turn discussions labeled with one of five intervention types (e.g. Factual Correction, Concept Definition) and an explicit conversational trigger; trains models to emit a special silent token when no intervention is needed; compares an integrated end-to-end model with a decoupled classifier–generator system "optimized for low-latency inference"; evaluates timing accuracy and response helpfulness — [arXiv 2508.18167](https://arxiv.org/abs/2508.18167)
- ProactiveLLM (Tong, Zhang, Zhao, Fan, Ma, Shen; arXiv 2606.00523, May 2026): streaming LLMs learn, from internal states only, whether partial input is semantically sufficient to respond, via mask-based streaming modeling and synchronized privileged self-distillation (partial-context student aligned with a full-context teacher view of the same model); supports plug-and-play decision heads without external teachers/annotations; reported to substantially reduce interaction latency on text and speech streaming tasks while keeping quality; code at the EIT-NLP StreamingLLM repo — [arXiv 2606.00523](https://arxiv.org/abs/2606.00523)
- Supergiant's GDC 2021 talk "Breathing Life into Greek Myth: The Dialogue of Hades" (Darren Korb, Greg Kasavin) covers fully voiced dialogue that plays after each player death and how the large script was optimized for audio production; the preview article does not describe selection mechanics — [Game Developer](https://gamedeveloper.com/audio/dive-into-the-dialogue-of-i-hades-i-at-gdc-2021); session page — [GDC Vault 1026975](https://gdcvault.com/play/1026975/Breathing-Life-into-Greek-Myth)
- Hades (Kasavin, GameSpot): "It's a simple system at heart, we just kept adding more types of conditions to check against as the game grew"; the team had no visual tool for mapping event connections, which made growing content hard to manage; example of state-reactivity: Megaera comments differently depending on whether the player beat her with Mirror upgrades active, and acknowledges when they are reset; three variations of a follow-up conversation depend on relationship state — [GameSpot](https://gamespot.com/articles/hades-writer-explains-script-philosophy-after-player-discovers-incredible-detail/1100-6482650/)
- Hades (Game Developer, 2020-02-13, summarizing Kasavin's RPS interview): the game checks mid-run state (e.g. an encounter can trigger when Zagreus' health is below a threshold) and delivers one of several pre-written events fitting the situation; developers can weight events to appear more often; the sequence stays partly unpredictable per player; "Reactivity has always been a goal of our narrative design"; the aim was to "take the pain out of dying and having to restart" — [Game Developer](https://gamedeveloper.com/design/how-supergiant-weaves-narrative-rewards-into-i-hades-i-cycle-of-perpetual-death)
- Moshi (Kyutai; Défossez et al., arXiv 2410.00037, Sep 2024): a full-duplex speech-to-speech model treating the user's and its own speech as parallel streams, needing no explicit turn segmentation so it can listen and speak simultaneously; "Inner Monologue" predicts time-aligned text tokens as a prefix to audio tokens; claims theoretical latency 160 ms and practical ~200 ms; criticizes cascaded VAD→ASR→LLM→TTS pipelines for ignoring overlapping speech, interruptions and interjections — [arXiv 2410.00037](https://arxiv.org/abs/2410.00037)
- Riera et al. (arXiv 2605.20356, May 2026) run two Moshi instances in simulated dialogue and find internal states "encode anticipatory information that supports turn-taking prediction ahead of time" (probed with causal LSTMs), with representational synchronization degrading under channel noise — [arXiv 2605.20356](https://arxiv.org/abs/2605.20356)
- Symbolically Scaffolded Play (Figueiredo & Elumeze, arXiv 2510.25820, Oct 2025): in a GPT-4o voice detective game, a within-subjects study (n=10) comparing high- vs low-constraint prompts found no reliable experiential difference except sensitivity to technical breakdowns; scaffolding stabilized the quest-giver NPC but reduced suspects' improvisational believability; conclusion: "tighter constraints do not inherently enhance play"; the authors moved to a hybrid JSON+RAG scaffold — [arXiv 2510.25820](https://arxiv.org/abs/2510.25820)
- KNUDGE / "Ontologically Faithful Generation of Non-Player Character Dialogues" (Weir et al., arXiv 2212.10618, Dec 2022, v2 May 2023): a dataset from The Outer Worlds side quests where generated branching dialogue must stay consistent with quest and entity specifications written in natural language (personas, backstories, relationships) and accurately reveal quest details; supervised and in-context models were "competent" with significant room left for game-quality dialogue — [arXiv 2212.10618](https://arxiv.org/abs/2212.10618)

### Inferences
- A MapleSyrup "remark hook" can be modeled exactly like a Valve response rule: {trigger concept (e.g. map_entered, bgm_started, hp_low, level_up), criteria over syrup-reported facts (map id, bgm id, player level band, job, party size, time in map, recent events), payload = a structured hook (topic, facts to mention, tone, intensity), memory flags}. Content lives in data (a per-map/per-event hook table), satisfying the founder's no-magic-strings rule; the LLM only phrases the chosen hook.
- Selection = Generative-Agents-style scoring, adapted: novelty (inverse of recency-of-last-use of this hook/topic with exponential decay), interest/importance (pre-rated per hook, plus a player-affinity term learned from stated preferences such as "Ellinia's music is the most beautiful"), relevance (match strength of criteria to the current state), with a hard specificity-first tie-break and per-topic cooldowns. Nothing fires unless a separate, fast "should I speak now" gate says yes (DiscussLLM's decoupled classifier is the right architecture for the 1 s / 0.5 s latency target).
- The GA failure modes are the exact risks for MapleSyrup: embellishment (inventing a composer or a reward), retrieval failures (forgetting the player said they prefer Ellinia), and stiff instruction-tuned speech. Mitigations: fact-slot filling only from the knowledge graph, an explicit "already said" memory per hook/topic, and style prompts/examples for casual speech.
- Concrete scoring sketch (derived from the cited systems, not itself sourced): score(hook) = w_rel·specificity_match + w_int·interest(hook, player_affinity) + w_nov·(1 − e^(−Δt_since_last_use/τ_topic)) + w_ctx·calm(state) − penalty(recent_topic_cluster); fire only if gate(state) says "speaking is welcome" (no combat, no low-HP alert pending, player not mid-sentence) and score > threshold; "remember" flags mark once-only hooks (e.g. first visit to Orbis), and a per-topic cooldown prevents two music remarks within N minutes. Reflection (GA-style, run off the hot path every few minutes) distils stated preferences ("Ellinia's music is the most beautiful") into player-affinity facts that raise interest for related hooks (piano arrangements, Ellinia-adjacent maps) — the mechanism behind the founder's "Wow, I swear, yes!" callback.
- Interest without hard-coded phrases: the hook payload should carry *facts and tags* (bgm_title="When The Morning Comes", mood=["gentle","morning","forest"], sentiment_source=TV Tropes, instrument_hook="piano arrangements are beloved"), and the voice model receives a style instruction to react in its own words; this is how maplestory.io/meowdb data becomes speech without any phrase living in code.

### Gaps
- Detailed mechanics of Hades' line selection (priority values, cooldown lengths, once-only flags) are in the GDC 2021 video, not in the text sources found; the text sources confirm only condition-checking, weighting and state-reactivity.
- Quantitative guidance on cooldown lengths or novelty decay constants for voice companions — no study found; the 0.995/hour decay and 150-importance reflection threshold from Generative Agents are for a day-scale social simulation and must be re-tuned for a 1–3 hour play session.
- No source measured how often a proactive companion may interject before players find it annoying; DiscussLLM evaluates timing accuracy on text discussions, not games.

## Key Question 4: Grounding suggestions in the player's real state

### Takeaway
Grounding must come from syrup's live observations (map, level, HP, party status) joined to a cached, version-scoped, provenance-tagged knowledge graph; the only official per-character API (Nexon Open API) is region-limited (KMS/TMS/MSEA), daily-refreshed and absent for GMS/Classic World, so it cannot supply "state at this moment". The literature's grounding failures (Generative Agents' embellishment, KNUDGE's faithfulness gap) argue for slot-filling facts from the graph and abstaining (silence) when a dependency is unobserved, stale or version-ambiguous, hedging only on taste. Critically, Nexon America's current policy note names "unauthorized screen recognition" software as a banned third-party-program category, enforced device-wide — MapleSyrup's observational design does not automatically exempt it, and this needs legal review and ideally express authorization from Nexon.

### Inferences
- The Nexon America developer's note is the single most important legal/product finding of this research: "unauthorized screen recognition" software is named explicitly as a banned category, and enforcement is device-wide while the game is open. MapleSyrup's entire premise (syrup = deterministic screen recognition) falls inside that wording even though it does not read memory, inject, or automate. Mitigation paths worth pursuing before scaling: (1) seek express authorization/partnership from Nexon (the policy's own test is "not expressly authorized by us"); (2) architect so the companion plausibly resembles tolerated streaming/recording software (capture via the OS screen-capture API like OBS, no process handles, no overlay injection, no input synthesis); (3) warn users in plain language; (4) build the B2B relationship with Nexon as a pathway to authorization. This needs a lawyer, not a researcher — but it must be surfaced to the founder now.
- Because WZ extraction (HaRepacker/MapleLib) means decompiling/deriving data from the client, it sits inside the EULA's reverse-engineering prohibition; MapleSyrup should prefer (a) its own observation (syrup reading names, levels, map titles and BGM cues from the screen/audio) and (b) licensed or user-contributed data over shipping WZ-derived datasets — and get legal advice before relying on fan APIs that are WZ-derived.
- "State at this moment" grounding: every suggestion template should declare the state variables it depends on (player level, map, party size, HP, channel) and the knowledge facts it depends on (PQ level range, EXP values) with freshness timestamps; the gate refuses to speak when any dependency is unobserved, stale (older than a per-fact TTL) or has lower confidence than a threshold — matching the founder's rule that a line about something no longer true is not said.
- Stay silent vs hedge: following the abstention literature's query/model/values split — abstain (silence) when the *query is unanswerable from observed state* (e.g. the player's level is not currently visible) or the *fact is version-ambiguous* (same quest name, different parameters); hedge aloud ("I think...") only for *taste* statements (music opinions), never for numbers. This keeps the voice stream honest without the "let me think" detour for every remark.
- Retrieval shape for 1 s latency: precompute per-map "hook packets" (BGM title, mood tags, NPCs, connected maps, level band of mobs, PQ eligibility rules, community-sentiment facts with sources) keyed by map id/name, so that when syrup reports a map change the candidate set is a local lookup, not a semantic search; the realtime voice model only phrases the chosen packet; Claude is reserved for open-ended planning questions.
- Hybrid architecture evidence: Symbolically Scaffolded Play suggests tight scaffolds help where coherence matters (quest-giver role = MapleSyrup's instructions/facts) and hurt where improvisation delights (suspects = MapleSyrup's small talk and opinions); so apply strict slot-filling to facts/suggestions and looser generation to banter — but still gated by the hook table so banter never asserts unverified facts.

### Gaps

- No published hallucination-rate measurements for game companions were found; the evidence is qualitative (Generative Agents, KNUDGE, Symbolically Scaffolded Play).
- Whether Nexon considers OS-level screen capture (as used by OBS/Discord) "screen recognition" when paired with recognition software is unanswered by any source found.
