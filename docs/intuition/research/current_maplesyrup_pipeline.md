## 0. Headline facts

- ~85k lines of Rust. Biggest files: `src/companion/mod.rs` (10,045 lines), `src/bin/maplesyrup/main.rs` (7,226), `src/ai/brain.rs` (5,923), `src/sight/mod.rs` (2,836), `src/metrics.rs` (2,686), `src/ai/mod.rs` (2,390), `src/phone/mod.rs` (2,270), `src/coach/mod.rs` (2,219).
- **No HTTP client crate.** `Cargo.toml` has `rustls`/`rcgen`/`ring` only for the phone's HTTPS *server*. All OpenAI / xAI / ElevenLabs calls are made by spawning the system **`curl`** binary per request (`src/ai/openai.rs:1-9`, `call_with` at `:374-522`) — a process spawn per LLM/TTS call, with `--no-buffer` streaming of the body via stdout and cancellation by `child.kill()` from a watcher thread polling every 15 ms (`:455-469`). This is a latency-relevant architectural fact.
- Two completely different conversation modes exist on master:
  1. **Turn-based ("Worker") mode** — phone browser speech recognition → text → OpenAI Responses API (or Grok) streamed → sentence-cut → TTS (ElevenLabs or OpenAI `gpt-4o-mini-tts`) streamed as 24 kHz PCM → played on PC speakers and/or the phone. (`src/ai/mod.rs`.)
  2. **Live-call mode** — the phone opens a WebRTC session directly to **OpenAI Realtime** (`gpt-realtime` / `gpt-realtime-mini` / `gpt-4o-realtime-preview`); the PC only supplies a short-lived key, the screen (`/api/eyes`), tools (`/api/tool`) and MapleSyrup's own lines to be relayed (`src/ai/live.rs:1-27`). On a call the PC-side Worker does not answer sentences.
  3. A third mode, **"Claude, live"** (`src/claude/`), pushes everything to a Claude Code session and speaks Claude's words; the Worker does not answer then (`main.rs:4035-4056`).
- README (master) advertises: streaming first-sentence TTS, barge-in ("you can talk over it"), three attitudes (Friendly / Blunt / Savage), a per-player notebook (memory), a coach that "speaks up when there is something worth saying", "stop coaching" voice commands, Grok (xAI) or OpenAI as LLM, ElevenLabs or OpenAI TTS, Windows voice fallback, 14 languages.

## 2. Conversation pipeline on master — end to end

### 2.1 Audio capture and speech recognition (phone side)
- **[master]** Speech recognition is done **in the phone's browser** with the Web Speech API (`window.SpeechRecognition || webkitSpeechRecognition`), `continuous = true`, `interimResults = true` (`src/phone/page.html:2108, 2288-2292`). There is no STT on the PC in turn-based mode. Raw 16 kHz mic samples are also POSTed to `/api/audio` for level metering, "speaking" detection and recording (`src/phone/mod.rs:7`, `src/phone/audio.rs`).
- Interim words are sent to the PC as `/api/hearing` (throttled to every 150 ms, `page.html:2148-2156`) → `Inbound::Hearing`; a finished sentence as `/api/heard` → `Inbound::Heard` (`src/phone/mod.rs:116-127`).
- **End-of-speech detection** is a **settle timer on the phone**: a sentence is sent when the interim words stop changing for `settleMs` — default **550 ms** (`page.html:2112-2115`), *not* waiting for the recognizer's `isFinal`. The PC can lengthen it adaptively: `status.settle_ms` from `learning.memory().adapt.settle_ms` (`main.rs:5069`) — the README's "It adapts how long it waits before answering". If the player goes on talking, only the new words are sent (`restOf`, `page.html:2142-2147`).
- **Half-duplex + barge-in**: while the phone plays MapleSyrup's voice, recognition is aborted and restarted `CLIP_TAIL_MS` after (`page.html:2206-2236`). The player can still talk over it: a loudness detector (`talkingOver`, `:2255-2265` — ≥5 consecutive loud frames over the floor) pauses the clip and POSTs `/api/interrupt` → `Inbound::Interrupt`; the PC does not trust that alone but waits for words (`main.rs:4202-4211`, `turns.loud`). On the PC side, `Turns::hearing` decides "talked over" vs "still talking" (`main.rs:4182-4201`, constant `TALKED_OVER`), and `Worker::cancel(id)` kills the in-flight curl and TTS (`src/ai/mod.rs:517-528`). `Job::Cut { heard }` keeps only the part actually heard in the conversation (`src/ai/mod.rs:357-359`, `Brain::cut_short` at `brain.rs:602-624`).
- **Own-voice echo filtering**: `companion.own_words(now, &heard, need)` strips MapleSyrup's own words heard back by the phone mic; a sentence begun while the PC voice played is treated as echo unless it is a local command ("mute", "mark that") (`main.rs:3980-4029`).
- **Wake word**: `companion.settings.always_listen` (phone toggle `Inbound::Listen(bool)`): when false, only sentences addressed to "syrup" are answered (`commands::interpret(&text, false) != Heard::NotForUs`, `main.rs:4128-4130`).

### 2.2 From a heard sentence to a job (PC main loop, `src/bin/maplesyrup/main.rs:3973-4181`)
Order of handling for `Inbound::Heard`:
1. Cancel any coach look in flight (`coach_job` → `worker.cancel`) (`:3976-3979`).
2. Echo removal (above). 3. If Claude mode → post to the Claude board and `continue`. 4. Local intents without a model: recording on/off (`commands::recording_request`), workshop ("change yourself…"), coaching on/off (`commands::coaching_request` → `set_coaching`), tone complaint (`commands::tone_complaint` → `drop_the_attitude`), "talk to me in Hebrew" (`out.language_asked`), objection to a taught thing ("I didn't level up" → mute it), local commands (`commands::local_command` → `companion.command`).
5. Pronunciation teaching (`ai::pronounce::heard`) → `Job::Say`.
6. **Instant answers**: `companion.instant(&text)` answers "their own numbers, and a hello on its own" with no model (`main.rs:4150-4163`, `src/companion/instant.rs`, 1,917 lines) → `Job::Say { heard, text }`; logged as `"timing", "instant answer"`.
7. Otherwise `conversation_job(...)` builds `Job::Converse { heard, snapshot, facts, speak, eyes, language }` (`main.rs:1953`) and `turns.asked(id, &text)` records the turn for barge-in bookkeeping.

### 2.3 The Worker (`src/ai/mod.rs`)
- `Job` enum (`:326-381`): `Converse`, `Speak` (own line: warning/alert/info, translated, shown and/or spoken), `Cut`, `Greet` (phone connected), `Say` (text already final), `Coach` (the coach's look: reason, label, snapshot, eyes, said-lately list, language, speak).
- `Done` enum (`:385-453`): `Reply{took}`, `Silent`, `Audio{samples, after, first, start, end, kind}`, `Failed`, `Noted`, `Shown`, `Command`, `Rewrite`, `Warn`, `LookUp`, `Coached{took, called_off}`.
- **Two lanes, one voice** (`spawn_brains`, `:592-965`): thread `"ai"` (thinking lane: Converse/Coach/Greet/Say/Cut) and thread `"mouth"` (`Job::Speak` own lines — a warning never waits behind a model call). A `floor` mutex serialises audio so two lines never overlap (`Mouth::floor`, `:986-989`, `speak_line` `:1061-1140`). The mouth lane reports what it said back to the thinking lane as `Work::Said` so the conversation keeps it (`Brain::watched`).
- **Only the newest `Converse` in the queue is answered**; earlier ones are skipped (`:709-712, 882`).
- **Cancellation**: every job has a number; `Worker::cancel(id)` raises a shared mark; `Stop::stopped()` is checked throughout; "kept" jobs (`Kind::kept()` — warnings/news) are immune (`Job::kept`, `KEPT_REMEMBERED = 64`).
- **Brains** (`:581-590`): `openai` (speaks, translates, fallback answerer), `fast: Option<OpenAi>` (Grok, `grok-4.3`, `XAI_BASE` `:164-166`), `eleven: Option<Eleven>`. The fast brain is given up after `FAST_GIVE_UP = 3` consecutive failures and rested `FAST_REST = 10 min` when it "loops" (repeats itself) (`:546-550, 921-948`).
- **`converse()`** (`:1700-2137`): builds `instructions = brain.persona() + EYES_GUIDE [+ CLASSIC_GUIDE] [+ TOOLS_GUIDE (+ LOOKUP_GUIDE)] [+ LEARNED_GUIDE + learned]` — stable part first "so OpenAI keeps it cached" (`:1722-1742`). Input = last `KEEP_TURNS=16` turns; only the last user turn carries the snapshot, the pictures (`Eyes::pictures()` = 640×400 low-detail JPEG with rulers; `close_pictures_for()` = 1280-wide + full-res close-ups when `brain::about_the_screen(heard)`), the `helps` from memory (`Learning::helps(heard)`) and an answer-language note (`input_of`, `:1413-1453`). `max_output_tokens: 150`, timeout 12 s for Grok / 40 s for OpenAI (`:1841-1850`). Up to 4 tool rounds (`toolbox.run_heard`), tools' `Effect`s become `Done::*`. Streaming: `brain::Sentences` cuts the token stream into sentences; `Saying::take` filters each (repetition via `Brain.recent`, unasked status lines via `brain::without_status`, unasked level-ups) and hands it to a scoped voice thread; **the first sentence is spoken alone, then everything written meanwhile in one piece** (`:1795-1835`). After the stream: `is_silent` → `Done::Silent`; "same as before" card deck when everything was repetition (`brain.same_as_before()`); `Done::Reply{took}`.
- **`coach()`** (`:1472-1609`): instructions = persona + `COACH_GUIDE` (+ learned); input = conversation turns + a user message `"[Not the player: your game watcher. Nobody said anything.]\n…snapshot…\n\n{reason}\n\nWhat you said on your own lately (don't repeat it, don't nag): …"` + small picture (`:1493-1520`); `max_output_tokens: 60`, timeout 12 s Grok / 20 s OpenAI; reply `[silent]` means nothing; the result is filtered through `brain.recent`, spoken as `Kind::Alert` via `speak_line` (when not on a live call) and returned as `Done::Coached`.
- **`greet()`** (`:2145-2225`): on phone connect; asks the model for a hello "picking up from last time" when there is a notebook, else `HELLO = "Hey! I'm here. Just talk to me."`.
- Translation of own lines into the player's language via a model call with a cache (`Translations`, `:1211-1405`; warnings wait at most 2 s for translation, other lines 20 s).

### 2.4 LLM providers, models, prompts
- **Client** `OpenAi` (`src/ai/openai.rs:301-311`): `key`, `base`, `voice`, `curl`, model list. Used for OpenAI and (with `XAI_BASE` + `GROK_MODEL`) for xAI; same Responses-API shape.
- **Models** (`openai.rs:21-39`): `CHAT_MODELS = ["gpt-6-luna", "gpt-6.1-sol", "gpt-5-mini", "gpt-4.1-mini", "gpt-4o-mini"]` (first the key accepts is kept); `VISION_MODELS` same set in another order; `SPEECH_MODEL = "gpt-4o-mini-tts"`, 24 kHz PCM; Grok `grok-4.3` (`ai/mod.rs:166`, "no reasoning: it answers at once"); Realtime `LIVE_MODELS` (`live.rs:37-41`), `TRANSCRIBE_MODEL = gpt-4o-mini-transcribe`.
- Requests set `"reasoning": {"effort": "none"}` and `"store": false`; retried without when a model rejects (`openai.rs:663-664, 751-758`).
- **Persona / system prompt** (`src/ai/brain.rs`): `PERSONA` (`:303-305`: "You are MapleSyrup: a fluffy cream-colored dog in a pancake-and-syrup hat, and the player's buddy…"), `style::RULES` (12 numbered rules: answer first, one short sentence under 12 words, never "let me check", gamer-friend voice, "Be dominant: you call the shots… have strong opinions", danger first, numbers rounded, don't describe the screen, no assistant-speak — `src/ai/style.rs:9-31`), `attitude_rules()` for Friendly/Blunt/Savage (`style.rs:34-54`), `MORE` (`brain.rs:308-327`: language, no repetition, trust eyes, corrections, presence rules — "greet only when your watcher says the phone just connected, never on your own; never ask whether they're still there", memory used "as a clause, never as a list", `[silent]` when the player talks to someone else), `who_he_is()` (name only from the player's own file; masculine Hebrew). `Brain::persona()` assembles them (`brain.rs:649-660`). Guides appended in `ai/mod.rs`: `EYES_GUIDE` (`:1143-1154`), `CLASSIC_GUIDE` (`:1161-1165`), `TOOLS_GUIDE` (`:1168-1182`), `LOOKUP_GUIDE`, `COACH_GUIDE` (`:1192-1199`: "React, don't report… Most of the time there is nothing worth saying: then reply with exactly [silent]… never ask them anything… never greet"), `LEARNED_GUIDE`.
- **Voice style prompt for TTS** (`brain::voice_style`, `brain.rs:272-300`): per attitude ("a warm, upbeat friend…" / "a cocky gamer friend…" / "a loud, sarcastic gamer friend roasting…") plus pace by `Delivery` (warning = urgent/faster, `Kind::Alert` = news, long reply = steadier). `Delivery` struct in `openai.rs:52-75`.
- **Live-call persona** `LIVE_PERSONA` + `LIVE_MORE` (`live.rs:50-111`) duplicates the rules for the Realtime model, incl. how to relay watcher lines ("HP's at 11, pot now"). The Realtime session uses `turn_detection: {type: "semantic_vad", eagerness: <Adapt.eagerness>, create_response: true, interrupt_response: true}` and voice `speed` `live::SPEED = 1.15` (`live.rs:156-177, 286-302, 375`); the player's words are also transcribed with `gpt-4o-mini-transcribe` for the log. On the branches: `REASONING_EFFORT = "low"`, `think_it_through`, `wait_for_user` tools and the sectioned prompt (see §3.5).

### 2.5 TTS / voice providers
- ElevenLabs (`src/ai/eleven.rs`, 520 lines) when the player picked a voice on the phone (`Learning.memory().voice`, `brain.rs:363-367`); falls back to OpenAI's voice on error (said once: "ElevenLabs didn't speak…", `ai/mod.rs:1098-1122`). `Eleven::speech_stream(text, voice, delivery, stop, on_samples)`.
- OpenAI `gpt-4o-mini-tts` streamed PCM (`openai.rs:809-837`); voice fallback `alloy`.
- Windows SAPI voice when no key (`src/platform/voice.rs`).
- Pronunciation rewriting before TTS: `pronounce::for_voice(text)` (`src/ai/pronounce.rs`, 1,733 lines); the player can teach pronunciations by voice ("Say X like Y").
- Output: PC speakers (`out.mouth.player`) with the game ducked (`platform/sound.rs`), and/or the phone (`VoiceOn::{Pc, Phone, Both, Off}`, `phone/mod.rs:85-114`). Audio reaches the phone as clips listed by `/api/state` with `kind` and `age_ms` (`phone/mod.rs:13-18`).

### 2.6 Game events → spoken alerts (the "companion")
- `companion.observe(tick.at, tick.obs)` returns `Action`s each frame (`main.rs:3806`); `Action::Say(s)` with `s.kind`/`s.speak` → `out.apply(...)` → `Job::Speak` on the mouth lane (`main.rs:3814`). `Kind` enum: `Warning`, `Alert`, `Info`, `Reply`, `Heard` (`ai/mod.rs:969-976` `label_of`). README `:31`: low HP/MP warnings, "a beating", death, level-up — "once per fight, again only when no potion answers it or the bar goes lower, never on one odd frame … held after four that nothing answers until you're back or ten minutes pass"; lines "dealt like a deck" (`companion::Deck`). Taught things' alerts fire via `tick.fired` (`main.rs:3895-3937`) with per-thing back-off (`fired.waits`) and session-mute on objection (`objections`).
- `companion.alerts_held(now)` (hold state) and `companion.muted()` gate everything.

### 2.7 Proactive speech: the coach (`src/coach/mod.rs`) — the closest thing to a "conversation director" today
- Module doc `:1-33`: "The companion says the little that is certain from the numbers… The coach is for the rest: it watches the game go by and decides *when* a model should look and *why* — and the model decides whether there is anything worth saying, in one line, or keeps quiet."
- `Glance` (`:42-61`): `now, obs, scene (Verdict: new_scene, activity), in_view, talking, muted, dead, held`. `talking` is computed in `main.rs:3827-3831` = PC voice playing || worker busy || turns busy || player heard < 3 s ago || player talking on a call < 30 s ago.
- `Reason` (`:65-81`), ranked by urgency: `CloseCall{lowest}`, `Streak{deaths, minutes}`, `NewScene`, `LevelUp{level}`, `ExpStalled{minutes}`, `Look`. `is_reaction()` (close call, streak) = said soon or not at all, without a picture. `describe(attitude)` (`:290-330`) builds the model prompt with example lines per attitude from `examples::*` (`:89-225`).
- **Pacing constants** (`:358-438`): `LOOK_EVERY = 45 s` growing ×1.5 per silent answer up to `LOOK_AT_MOST = 180 s`; `TALK_WINDOW = 300 s` (each second of talk in the last 5 min delays the next idle look by a second); `MIN_GAP = 15 s` after anything said; `CONSULT_GAP = 8 s`; `CLOSE_CALL_UNDER/BACK/WITHIN/AGAIN = 10% / 40% / 20 s / 300 s`; `STREAK_DEATHS = 3 in 600 s`; `STALL_AFTER = 180 s` (of active play), `STALL_AGAIN = 600 s`; `LEVEL_UP_AFTER = 6 s`; `NEW_SCENE_AGAIN = 120 s`, `NEW_SCENE_HUSH = 10 s`; `IDLE_ACTIVITY = 0.002`; `SETTLE_IN = 10 s`; `STALE_AFTER = 60 s`; `CONSULT_TIMEOUT = 45 s`; `KEEP_LINES = 6`.
- `Coach::observe(&Glance) -> Option<Reason>` (`:699-822`) is the decision function; `propose()` keeps one pending reason (highest rank wins, `:926-931`); `consult()`; `answered(now, line)` adapts `look_every`; `called_off()`; `someone_spoke(now)`; `leveled()`; `set_on()`; `lines()`.
- The main loop (`main.rs:3819-3876`) calls it every frame, builds `Job::Coach` with `reason.describe(attitude)`, snapshot, optional `Eyes`, `coach.lines()`, and `speak: !out.live`. The look's result returns as `Done::Coached` → `coach.answered/called_off` (`main.rs:4695-4730`).
- Coaching toggles: phone `Inbound::Coach(bool)`, voice "stop coaching"/"coach me" (`commands::coaching_request`), tool `set_coaching`; persisted in `learning` (`set_coaching(&mut coach, &learning, …)`).

### 2.8 Conversation memory and state
- Short-term: `Brain.turns` (`KEEP_TURNS = 16` pairs; replies cut to `REMEMBER_REPLY_CHARS = 240`), `Brain.recent: Recent` (what was said in the last 10 min / 80 sentences, fuzzy-matched by ≥80% shared words, numbers folded in long sentences — `brain.rs:13-217`), coach's `said` (6 lines), `companion.remember_spoken`.
- Session facts for the model: `SoFar` → `presence()` (`brain.rs:773-826`: quiet_before, since_player_spoke, deaths, level_ups, lowest_hp_lately, quiet_for) and `snapshot_with_view()` (`:833-899`: window state, character line, bars, session length, EXP/h, ETA to level).
- Long-term: `ai::memory::Learning` ("notebook") — see §2.9.

### 2.9 Long-term memory: the "notebook" (`src/ai/memory.rs`, 1,542 lines) **[master]**
- Module doc `:1-21`: "What MapleSyrup learns about the player from playing together, kept in `memory.json` in the settings folder and used in every conversation. Nothing has to be taught. Every few minutes, and when MapleSyrup starts, the learner reads what was said in the session logs and has the model update its notebook… It also counts how talking goes and adapts to it."
- `Memory` struct (`:195-235`): `facts: Vec<Fact>` (≤ `MOST_FACTS=40`), `style: Vec<String>` (≤8, "how they like it to talk"), `words` (≤40, vocabulary for STT hints), `last_time: String`, `sessions`, `counts: Counts`, `adapt: Adapt`, `forgotten`, **`attitude`**, **`voice`** (ElevenLabs id), **`coach: Option<bool>`**, `updates`, `workshop`, `workshop_coder`. Saved atomically (`.json.partial` + rename, `:252-266`). This struct is where **all conversation settings** live today (not `config.rs`).
- `Adapt` (`:103-192`): `settle_ms` (`SETTLE_MIN=400`, `SETTLE_MAX=1300`, `SETTLE_START=550`) adapted from the rate of "continued" sentences (>20% → +150 ms, <5% → −50 ms); `eagerness` for Realtime semantic VAD ("high"/"medium"/"low") adapted from "jumped in" rate; `short: bool` (player talks over >30% of replies → "keep it to one short sentence"); `hp_low`/`mp_low` overrides.
- `Memory::prompt()` (`:270-300`) renders "What you know about them:" / "How they like you to talk:" / "Lately: …". `Learning` (`:727-732`) = `Arc<Mutex<Memory>>` + `Arc<Mutex<Knowledge>>` + settings dir; `Learning::prompt()` (`:863-881`) = about-me.txt lines + notebook + last 12 lessons; `Learning::helps(text)` (`:885-888`) = 3 relevant knowledge entries by word overlap.
- The **learner thread** (`spawn`, `:983-1066`): every 5 s wakes, every ≥20 s reads session logs (`read_logs`), and when `due()` (≥30 player lines, or ≥6 after 4 min, or ≥2 after 8 min) asks the model with `look_back()` (`:642-699`, JSON-schema output, 2000 tokens, 90 s timeout; `LOOK_BACK` prompt `:701-720`) to rewrite the whole notebook; new lessons go into `Knowledge` with `Source::Player`; counts feed `Adapt::learn`. The player's own `about-me.txt` (`TOLD`) is the only source of his name (`name_in`, `:768-795`).
- The phone shows the notebook with Forget buttons (`Learning::status()`, `:928-968`; ids `m:`/`s:`/`a:`/`k:`).
### 2.10 Game knowledge on master — small **[master]**
- **`src/knowledge/`** (295 lines total): `const` Rust data — `MONSTER_BEHAVIORS` (a handful of early-game monsters: name, aggro, movement, threat note, `monsters.rs`), `RUNE_MECHANICS`, `PORTAL_MECHANICS`, `FARMING_HEURISTICS` (`mechanics.rs`, 48 lines), dialog keyword classification (`dialogs.rs`). Zero-sized `KnowledgeBase` handle (`mod.rs:34-60`). ### 2.11 Latency instrumentation and measurements
**[master]**

- **Where the time goes on master's turn-based path** *(inference from the code; no end-to-end measurement on master)*: phone settle wait 550 ms (adaptive 400–1300) → HTTPS POST to the PC (LAN, or via a Cloudflare tunnel) → main loop poll (frame tick) → `Job::Converse` → `curl` spawn + Responses API stream (Grok 12 s / OpenAI 40 s timeouts; `reasoning.effort: none`) → first sentence complete (`brain::Sentences`, `SENTENCE_MIN_CHARS = 16`) → second `curl` to TTS (ElevenLabs or OpenAI) → first PCM chunk → PC playback at once, or the phone fetches the clip **only once the line is complete** (`Outputs::play_piece`: "on the phone a line at a time, once the line is complete") and plays it. The PM doc (`:105`) notes the same: "when the voice comes from the phone, the phone gets a sentence only once it is whole". The 1 s target therefore has to cut: the settle wait, one of the two serial network round trips (LLM then TTS), the curl process spawns, and the whole-clip-before-play on the phone.

### 4.1 (a) Background "thought loop" — candidate remarks and suggestions from game state, memory and persona
Where it plugs in:
- **Trigger/pacing**: extend `coach::Reason` (`src/coach/mod.rs:65-81`) with new reason kinds (e.g. an idea about the map, a tip from knowledge, small talk, a memory-based callback), proposed through `Coach::propose()` (`:926-931`) so they inherit rank ordering, `STALE_AFTER`, `MIN_GAP`, `CONSULT_GAP`, hold/mute/talking gating. Alternatively a sibling struct fed from the same place in the main loop (`main.rs:3819-3876`, where `Glance` is built) that *produces* candidates asynchronously while `Coach` keeps deciding *when*.
- **Generation**: today the coach's look *is* the generation — one model call per reason (`ai::coach()`, `ai/mod.rs:1472-1609`, `Job::Coach`), prompt = persona + `COACH_GUIDE` + snapshot + `reason.describe(attitude)` + `said` list (+ picture on master; no picture on the branches). A background thought loop would be a new `Job` variant (or a separate low-priority worker thread alongside `"ai"`/`"mouth"` in `spawn_brains`) that pre-computes candidate lines **ahead of the moment**, caches them (with a validity `Basis` like the branches' `Board::Basis`: map, alive/dead, level) and lets the director pick one when a gap opens — so the 12–20 s model timeout is off the critical path.
- **Inputs available**: `snapshot_text()` (`main.rs:1683-1708`: HUD numbers, session, presence, `sight.describe()` lines, Classic-World flag), `Facts`, `coach.lines()`, `Learning::prompt()/helps()`, `Knowledge::relevant()`, `coach::scene::Verdict.activity`, `Companion::so_far()`, taught-things events (`tick.fired`), and — on the branches — `fresh::Values` (live numbers filled at speech time).
- **Memory of what was said**: `Brain::watched(label, line)` (`brain.rs:582-597`) keeps an unprompted line in the conversation as a watcher turn; `Coach.said` (6 lines); `Recent`.
- **Persona/taste**: currently nothing stores MapleSyrup's *own* opinions/tastes — only how it talks (attitude / spectrum level) and what it knows about the player. The natural home is a data file beside `spectrum.json` (e.g. `companion/persona.json` loaded with `include_str!` + serde, `OnceLock`) feeding `Brain::persona()` and `Reason::describe()`.

### 4.2 (b) "Conversation director" — whether and when to say a candidate
- The decision function already exists: `Coach::observe()` (`coach/mod.rs:699-822`) with inputs `Glance { now, obs, scene, in_view, talking, muted, dead, held }`. **Game intensity** = `scene.activity` (`IDLE_ACTIVITY` threshold; the frame fingerprint in `coach/scene.rs`), plus `companion.dead()`, HP via `obs.hp` and `CloseCalls`. **Player speaking** = `Glance.talking` computed at `main.rs:3827-3831` (PC voice playing, worker busy, `turns.busy()`, player heard <3 s, call talking <30 s) plus `player_quiet()` for holding own clips. **Cooldowns** = the `const`s at `coach/mod.rs:358-438`. **Chattiness**: on master only the `coach` on/off toggle (`Memory.coach`, `Inbound::Coach`, `set_coaching`, tool `set_coaching`) and the self-adapting `look_every`; on the branches the wildness bar (`spectrum.json`) is a *tone* setting, not a chattiness one — a chattiness level would be a new field in `Memory` (persisted, phone-exposed like `tone`) that scales `LOOK_EVERY`/`MIN_GAP`/`TALK_WINDOW` and the acceptance threshold of candidates.
- **Delivery path** for a chosen line: `Done::Coached` → main loop (`main.rs:4689-4731`) → `coach.answered()`; spoken inside the worker via `speak_line` as `Kind::Alert` when not on a live call, else `out.tell(Kind::Alert, …)` → `Relay` → the call says it in its words. For a pre-generated line, `Job::Say { heard: None, text }` (shown + spoken, kept in the conversation) or `Job::Speak { kind: Kind::Alert|Info, … }` on the mouth lane are the existing entry points (`ai/mod.rs:349-366`); `Kind::Info` is *not* `kept()`, so a talk-over cancels it — the right kind for small talk.
- **Barge-in safety**: anything the director says must go through `Worker::send` so `Worker::cancel`/`Turns::interrupt` can stop it; `Outputs::play_piece(hold = own && !player_quiet)` already delays own lines while the player talks (`main.rs:4820-4836`).
- **Live-call mode**: the director's lines reach the Realtime model as watcher messages (`hub.post_with_fact`, `LIVE_MORE` tells the model how to relay them); the branches add `QUIET_TOOL` for the inverse decision (the model staying quiet).
- **Claude mode**: the equivalent director is Claude itself, briefed by `kit/CLAUDE.md` ("When to speak on your own… Otherwise stay silent"), with `Feed` deciding which events are pushed (`src/claude/feed.rs:1-10`) and, on the branches, `Board::Basis` refusing stale lines and `ANSWER_WAIT` safety net.

### 4.3 (c) Persona/taste data and long-term memory of the player
- **Player memory** exists: `ai::memory::Memory` (facts ≤40, style ≤8, words ≤40, last_time) updated by the learner's `look_back()` with a JSON schema (`memory.rs:642-720`), `Knowledge` lessons/look-ups, `about-me.txt`. Extending it = add fields to `Memory` (`#[serde(default)]` keeps old files loading), add them to the `look_back` schema/prompt and to `Memory::prompt()`/`Learning::status()` (phone). The notebook goes with every reply (`LEARNED_GUIDE`), the coach look and the live call.
- **MapleSyrup's own persona** is prompt text: `brain::PERSONA`, `MORE`, `style::RULES`, `attitude_rules()` (master) / `spectrum.json` level `instructions` (branches), `voice_style()` for TTS, `live::LIVE_PERSONA`/`LIVE_MORE`, `CLAUDE.md`. Tastes/opinions/enthusiasm/humming have no representation yet; the branch's data-file pattern (`spectrum.rs`: `include_str!` JSON → `OnceLock`, tests that validate the data) is the established way to add such data without "magic strings" in logic.
- **Session-level self-state** (what it said, mood over the session) exists only as `Brain.recent`, `Coach.said`, `Companion::remember_spoken`, `SoFar` — no explicit "mood"/"interest" state.


## 5. Coding conventions observed (for new code to match)
- **Docs**: every module opens with a `//!` prose doc (often with an ASCII diagram) that says what it is for and *why* decisions were made, citing real incidents with dates ("on 25.10 the tester heard…", "the owner's 'Talk to me you fucker' got exactly that"). Every `pub` item has a `///` doc; tunables are `const`s with doc comments at the top of the module (`coach/mod.rs:358-438`, `companion/mod.rs:190-211`). Comments are plain English prose, parentheses for asides. Names are words, not abbreviations (`Glance`, `Reason`, `Turns`, `Mouth`, `Brains`, `heard`, `said`).
- **Error handling**: no `anyhow`/`thiserror`; hand-written enums with `Display` (`ai::AiError`, `openai.rs:77-147`), `Result<_, String>` for tools, `Option` for "nothing to say". Locks are taken with `lock().unwrap_or_else(|e| e.into_inner())` (poison-tolerant). Side effects that may fail are `let _ = …`. No `unwrap()` in production paths except on `std::thread::Builder::spawn` results discarded with `let _`.
- **Concurrency**: `std::thread` + `std::sync::mpsc` channels, `Arc<Mutex<_>>`, atomics (`AtomicU64` marks for cancellation via `Stop`); named threads (`"ai"`, `"mouth"`, `"learner"`, `"talk-over"`); no async runtime.
- **Time**: domain logic takes `now: f64` seconds (companion, coach) so it is testable by replaying sessions; `Instant`/`Duration` in the binary.
- **Data files**: `include_str!`/`include_bytes!` compiled in (`phone/page.html`, `dog.js`, `spectrum.json` [branch], `sight/delimiters.json` [branch], `assets/companion/dog-parts.json`), parsed once into a `OnceLock` with a test that validates the data (`spectrum.rs` tests). Persistent state is pretty JSON in the settings folder written atomically (`.partial` + rename). Lines spoken by MapleSyrup itself are `const` arrays per attitude dealt from a `Deck`.
- **"No magic strings"**: explicitly enforced in review on the new branches — commit 3fdc689 ("Review: no magic strings. The word lists this PR added are gone… the model judges the rest"), 46bf433 ("with no word lists"), 6d3ac05 ("no word lists"); constants name every protocol string (`live::THINK_TOOL`, `QUIET_TOOL`, `latency::field::*`, `tools::COACH_ON`, `fresh::SLOTS` "the one list"). **But master still contains many English/Hebrew phrase lists in logic** from before (`brain.rs:136-155` `asks_again`, `:940-1030` `ASKED`/`ASKING`, `companion/commands.rs`, `companion/instant.rs` `HELLOS`, `memory.rs:746-762` `NAME_SAYS`, `knowledge.rs:56-64` `COMMON`) — "Word lists from before this PR are as they were" (3fdc689). New code is expected to let the model judge intent (tools like `set_tone`/`set_language`/`wait_for_user`) rather than match phrases, and to keep any texts in data files.
- **Tests**: unit tests in `#[cfg(test)] mod tests` at the bottom of each file with sentence-style names (`the_coach_is_told_to_react_in_its_attitude_and_never_to_narrate`); integration tests in `tests/` run real components against **stand-in HTTP servers on 127.0.0.1** through the same `curl` path (`tests/openai_fake.rs` 3,322 lines, `tests/eleven_fake.rs`, `tests/phone_link.rs`, `tests/latency_trace.rs` [branch]); session replays for companion/coach pacing; Playwright scenarios for the phone page in `tools/phone_ui_check.py`. Prompt texts are pinned by tests that assert key phrases (`ai/mod.rs:2281-2296`, `style.rs:65-88`). CI (`.github/workflows/ci.yml`): `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --release` on Windows with Tesseract; README says ~420 tests (commit e26cdb7 says 681 on the branch).
- **Commits**: conventional prefixes (`feat(call):`, `fix(turns):`, `docs(pm):`, `test(bench):`), long bodies explaining the incident, the decision maker ("The owner's direction…", "The PM's call…") and what was checked; `[skip ci]` for bench-only commits; `Co-Authored-By: Claude …` + `Claude-Session:` trailers.
- **Layout**: `src/lib.rs` lists modules with one line each; `src/bin/maplesyrup/main.rs` holds the orchestration (`Outputs`, `Turns`, `Relay`, `Mouth`), library modules hold testable logic. Prompts live as `const &str` next to the code that sends them.

## 7. Gaps relevant to the founder's goals (what does **not** exist yet, on any branch)
- No background thinking between turns: every unprompted line is one synchronous model call made when the coach decides to look; nothing is pre-computed or cached.
- No representation of MapleSyrup's own tastes/opinions, moods or enthusiasm; no humming/non-verbal vocalisation path (TTS gets plain sentences; `pronounce::for_voice` rewrites words only).
- No small-talk-about-the-game-world generator: `Reason::Look` asks the model to react only to danger/stall/idle; `COACH_GUIDE` forbids greeting, questions and comments "for the sake of it"; `companion/chat.rs` small talk is a fixed card set.
- No chattiness dial (only coach on/off and tone); no explicit game-intensity model beyond `scene.activity` and HP/death state.
- No end-to-end latency budget on master from end-of-speech (the branch's `util/latency.rs` provides it, opt-in). Architectural latency costs on master: a `curl` process per request, the phone's 550 ms settle, TTS as a second network round trip, the thinking lane being serial (a coach look blocks a reply until cancelled).
- The game knowledge available to the conversation is whatever the model knows plus `knowledge.json` lessons/look-ups; the structured `src/knowledge/` data is not used by the conversation.
